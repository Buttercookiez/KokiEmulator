# Koki NDS native Android 0.2.1

Android ARM64 uses melonDS-android-lib at 431ab4bd0003c4356e25fce89640ae1004579b9b, https://github.com/rafaelvcaetano/melonDS-android-lib. The complete pinned source is included in the release source archive under upstream/melonds. It contains vendored teakra, FatFs, FreeBIOS and JIT sources. Koki bridge source is native/nds/ (C++, Java, manifest and CMake). The owner approved GPL-3.0-or-later distribution of Koki NDS; see LICENSE-NDS.txt and bundled notices. Third-party license grants remain intact.

The backend runs emulation on a HandlerThread, with ARM64 JIT (fast-memory mapping disabled) and a threaded software 3D renderer. The checked-in bounded-memory patch allocates only DS RAM and disables unused mirrored address spaces and fault handlers. Native-window frames and AudioTrack PCM stay outside JavaScript. ROMs are opened directly from the private library without whole-ROM JavaScript/base64 copies. JS sends only input, layout/settings and save requests; screenshots/checkpoints are explicit one-shot transfers. No game ROMs or Nintendo BIOS/firmware are included. Open FreeBIOS and generated firmware are used. DSi, wireless, microphone and camera are not connected.

## Rebuild

Use Windows, Node 22.12+, npm, JDK 21+, Android SDK/platform 36, NDK 27.1.12297006, CMake 3.22.1, and Microsoft Edge for icon generation. Install dependencies with npm ci. Set ANDROID_HOME and JAVA_HOME if installed elsewhere. Run npm run nds:android. The sync script fetches the exact pinned core and checks its revision and tracked cleanliness, then verifies and applies native/nds/bounded-memory-patch.json to a separate build tree; the build uses no runtime core downloads. For an offline source-archive build, copy upstream/melonds into .cache/native-nds/core and run the sync script with KOKI_NDS_OFFLINE_SOURCE=1. The archive contains all native core source, frontend source, Android project template, package-lock and integration/build scripts. SDK/JDK/NDK/npm dependencies are standard external build tools/components. The APK preview is signed using the existing local Android debug key; it is not a Play production build. A clean workstation uses its own debug key, so its APK cannot update a differently signed installation.

The default APK ABI is arm64-v8a (including Redmi Note 10 Pro). KOKI_NDS_ABIS=x86_64 builds a separate emulator-test APK. CMake enables JIT and disables Qt/SDL, OpenGL, GDB and release LTO. Native shared-library LOAD segments use 16 KB alignment. C++ runtime is linked statically. The Windows build continues using the pinned SkyEmu WebAssembly core and its existing engine ID; npm run nds:desktop builds that app. Rebuilding the compatibility core requires the separate Emscripten toolchain documented in NDS-CORE.md.

## Saved progress and compatibility

Settings → DS engine selects Native or Compatibility on supported Android builds. Starting an old SkyEmu checkpoint selects Compatibility automatically; selecting a native checkpoint selects Native. Automatic resume chooses only the active engine's checkpoints. A native checkpoint is not portable to SkyEmu/Windows. Native snapshots use engine ID melonds-431ab4b-android-v1 and a KOKIMLN1 envelope containing the game hash, pinned core tag, raw size and CRC32. Corrupt or wrong-game envelopes are rejected before the core receives them.

Native checkpoints restore their own cartridge save memory; an unrelated fallback battery file is not loaded first. A raw old .sav is copied into native memory only if its length matches the native core's expected save size. The old file remains untouched. Native progress is stored in a separate <game>.native.sav with its own previous version; Compatibility retains <game>.sav. Full library ZIPs preserve both save families and all checkpoint engine tags. Native automatic checkpoint rotation never prunes compatibility checkpoints. Export saves using the corresponding selected engine. Back up before updating; uninstalling Android removes app-private data.

## Test scope

This is an experimental performance candidate, not a full-speed guarantee. Generated dual-screen homebrew tests on an isolated API 36 x86_64 Android emulator verify the bridge and native JIT path. An ARM64 APK is cross-compiled and inspected. Physical Redmi Note 10 Pro / Zelda gameplay, sustained thermals, external gamepads and Bluetooth latency need device testing. Results are recorded with the release verification file. Windows/SkyEmu compatibility checks remain separate from native Android tests.

## Audio and mobile update 0.2.1

AudioTrack receives complete blocking PCM writes and starts after a bounded 40–50 ms preroll. Pause, resume, rewind and restore re-prime that buffer. Native mixing uses 16-bit output and cubic interpolation, including when restoring older native states. The untouched landscape preset migrates once to a compact diamond and separated outer Start/Select controls; customized positions/sizes are retained. Mobile side-by-side view uses narrower gutters.
